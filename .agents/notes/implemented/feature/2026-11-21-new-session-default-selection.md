# Agent Note: 独立的新会话默认能力选择

Status: implemented

## Problem

「新会话沿用能力库开关」只有总开关，用户为下一条会话挑选能力时仍需修改全局库，影响既有会话。需要一套持久化默认选择，而不是多预设管理。

## Decision

在 settings.json 增加 libraryDefaults：缺失或 null 表示兼容当前库开关；对象 {mcp:[],skills:[]} 表示明确选择，即使两者为空。总开关仍独立。原卡片右侧配置按钮通过现有 Modal 编辑草稿，保存经 settings 路由持久化，取消只丢弃草稿；恢复沿用能力库写入 null。专用只读目录路由投影名称、描述、可用性以及安全的来源元数据，不返回连接配置或技能路径。

新根会话沿现有 agent/created → seedFromWorkspaceDefault 链路初始化；独立配置与当前真实作用域的可用目录取交集，工作区声明 MCP 保留现有基线。工作区显式预设（含空集）、已有策略与子代理父链优先级不变。保存不修改 registry、技能 frontmatter 或会话策略。

2026-11-21 补充：配置弹窗沿用 provider / bundle owner 来源分组，显示插件包名、组内已选数；系统、自建 MCP、未归属插件与目录暂缺项分别展示，默认全部展开。搜索支持插件名且不影响隐藏勾选。新客户端搭配旧宿主时从已有目录路由补齐来源，失败显示「来源待识别」，不从描述或名称猜插件，也不覆盖权威可用性与选择。

## Alternatives considered

- 直接复用能力库全局开关：不新增存储且即时兼容，但为了准备下一会话而修改库会影响当前会话，违背隔离目标。
- 保存成现有工作区预设：可复用存储与初始化分支，但用户要求跨工作区的一套默认值，工作区预设本身必须继续优先，故保留两层。
- 客户端单独保存选择：实现最快，但宿主创建会话时读不到，刷新与多客户端状态也易分裂，故复用宿主持久化。

## Consequences

- 收益：选项跨刷新与插件重载保存；明确空集不恢复库里的开启项。新会话拿到独立允许项，保存与总开关互不覆盖。
- 代价：保存的是名称而非能力副本。目录随工作区与 preset 变化，暂缺项保留以供回显和清理，创建时只授予当前可用项；工作区专有能力仍走原有规则。客户端可能新于宿主，缺新字段时配置按钮不可用，提示升级；旧总开关仍正常。
- 验证路径：`test/session-caps-smoke.mjs` 走实际 HTTP handler、落盘、插件重载及 agent/created，覆盖固定/空选、总开关、已有会话、工作区优先和子代理继承；`test/client-render-smoke.mjs` 验证弹窗的加载、草稿取消、选择和保存回显，以及插件归属分组、按插件名搜索、隐藏勾选保留、不可用项与旧宿主来源补齐。2026-11-21 分组补充已通过九项相关回归；将插件归属标题故意改错后新增断言变红。独立无头 Chromium 使用宿主静态表内真实 React / Button / Switch / Modal、原生主题和生产客户端，对当前宿主只读目录请求验证分组与搜索，并逐张检查浅色、深色、窄屏截图；取消没有发送写请求，真实设置前后相同。
