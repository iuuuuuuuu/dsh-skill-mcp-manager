# Agent Note: 非插件 MCP 与技能编辑

Status: implemented

## Problem

用户能新增 MCP，却没有明确的修改入口；技能只能外部打开。需要在能力库直接编辑自己的能力，并保证插件提供的条目不被新编辑接口改写。

## Decision

能力库卡片以原生 Modal 提供编辑。MCP 只编辑既有非插件注册表名称，字段复用注册函数校验与试连，明确提供离线跳过选项；保存保留 pin、loader id 和禁用工具，连接变化清除旧检测并回收旧按需连接。技能只接受系统 provider 的文件型定义，在租约内解析名称并检查原路径和真实目标的只读属性；完整 SKILL.md 共用发现解析器验证后原子替换，文件模式保留，缓存失效后重新发现。

名称保持不变，避免让会话允许项、工作区预设和默认选择失去目标。两类编辑使用 revision 与串行写队列，技能在替换前再次比对外部变动；MCP 真实试连完成后、写盘前再次检查 revision 与来源，防止较慢握手覆盖同期的档位或配置修改。取消不写入；旧宿主缺新接口明确报未加载，不借旧写入口绕过来源守卫。

## Alternatives considered

- 复用新增表单、输入同名条目：注册逻辑可复用，但缺原值回填、遗漏字段易丢失，也没有明确的来源限制；保留同一注册函数，另加受保护的读取与更新入口。
- 技能仅继续用系统编辑器：无需维护文本界面，适合外部工具用户；但会抢焦点且不满足页面内修改，故保留原入口并提供本地弹窗编辑。
- 编辑时同时改名：用户可直接调整标识，但需要迁移所有历史策略和引用，超过本次修改诉求；本次固定名称。

## Consequences

- 收益：自有 MCP 和技能可直接修改，插件与随包文件在后端保留内容边界；失败保留原件和草稿，显式空值可清除旧配置。
- 代价：文件外部编辑器不参与本进程写队列，使用 revision 和替换前比对检测冲突；名称修改另需完整引用迁移。宿主新增路由需要加载新的后端，客户端缺接口时不假装保存成功。
- 验证：capability-edit-smoke 通过真实 HTTP、真实 stdio 与实际文件校验保存、插件/只读限制、失败不落盘、冲突和并发。原生 React/Button/Modal 的独立 Chromium 实测保存与取消、插件无入口、JSON 错误及外部冲突，并检查浅色、深色和窄屏截图。完整 31 项发布基线通过；独立副本中移除 provider 后端守卫、移除插件卡片入口条件，分别在预期的 HTTP 状态断言与界面断言变红。当前运行宿主的新编辑路由仍返回 404，属于待重启加载的新后端，未以刷新网页冒充部署成功。
