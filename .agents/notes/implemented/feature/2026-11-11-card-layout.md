# Agent Note: 管理页卡片化（列表行 → 卡片网格 + 详情抽屉）

Status: implemented

## Problem

管理页原来每个 Skill / MCP 是一行：名字、徽标、描述挤在一行里，操作按钮固定在行尾，环境变量、headers、工具清单全部就地展开在行内。用户的原话是「不是卡片化」。行式布局在设置页这种窄容器里有两个实际后果：一是条目一多就变成一堵长条，同一屏看不到几个；二是行内展开详情会把相邻行推出视野，滚动位置也跟着乱。项目原有的 UI 是「列表 + 行内详情」，这不是视觉偏好问题，而是信息层级没有分层——概要信息和细节信息被塞进了同一条横向流里。

## Decision

Skill 与 MCP 都改成自适应卡片网格（`grid-template-columns:repeat(auto-fill,minmax(240px,1fr))`，设置页宽度下两列），每张卡片只放概要：名字、路径或传输方式与工具数、档位下拉、状态圆点、最多三行的描述、以及属于这张卡片的操作按钮。

细节信息（环境变量、headers、工具清单、命令与参数、使用说明、逐工具启停、peek 输出）移进右侧详情抽屉：`position:fixed` 的 `.smx-drawer`，点遮罩或「关闭」退出。抽屉必须用 fixed 而不是就地展开，否则它会被设置弹窗的滚动容器推着走、把卡片撑高。实测该 fixed 覆盖层能盖住设置弹窗（Chrome headless 截图确认 x=647 w=509 覆盖到窗口顶部）。

MCP 页顶部的两条数字输入（工具描述截断、stdio 消息上限）收进可折叠的「高级设置」：它们是一年改一次的配置，却比所有卡片都先出现，把卡片推到首屏之外。默认收起。

状态圆点承担「一眼判断」：绿=连通、红=失败、蓝色脉冲=检测中、灰=未检测。

## Alternatives considered

- **保留行式但改进间距**：改动最小，但解决不了「细节撑高列表」的根因——只要详情还在行内，条目数量一多就还是长条。
- **卡片 + 就地展开详情**：省掉一个覆盖层组件，但展开会让网格行高抖动、卡片在一列里被拉得很长，反而比行式更难扫视。
- **整页改成独立路由页（而不是设置页里的 section）**：空间更大，但要把插件的 slot 从 `settings.section` 换成别处，还牵动「能力库」入口与宿主 slot 契约；本次目标只是把既有面板的层级理顺，不值得为布局改挂载点。
- **用 UI 组件库 / 引入构建工具**：项目硬约束是纯 JS、无 JSX、无 bundler（client.js 是单文件 bundle），卡片只需要少量 CSS，引入依赖的成本远大于收益。

## Consequences

- 新增 CSS 类（`.smx-cards/.smx-card*/.smx-dot*/.smx-drawer*`）全部集中在 client.js 的 `CSS` 数组；旧的 `.smx-list/.smx-row*` 已删除，别再按行式加回来。
- 设置页宽度决定列数：240px 是最小宽度，窄窗会退化成单列——这是有意的，比强行两列压扁描述好。
- 抽屉是 fixed 覆盖层，如果宿主以后给设置弹窗加 `transform`，fixed 会退化成相对该容器定位，需要改回 portal 或提高层级；届时用真实截图确认。
- 交互行为（启停、删除、档位切换、刷新快照）全部沿用原 RPC，没有新增后端能力。
